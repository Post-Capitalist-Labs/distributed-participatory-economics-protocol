## 1. Evaluation of the Four Candidate Architectures

We compare the four architectural paradigms specified in Section 5 of the Research Brief:
- **Architecture A — Conventional Distributed Services:** Federated PostgreSQL/SQL databases, REST/gRPC authenticated APIs, replicated cloud/community servers, and event-driven message brokers (Kafka/NATS).
- **Architecture B — Pure Peer-to-Peer Distributed Protocol:** Content-addressed data (IPFS/Iroh), DHT/mDNS peer discovery, libp2p gossipsub, authenticated messages, and CRDT state replication without a global consensus layer.
- **Architecture C — Blockchain / Distributed Ledger:** Application-specific Byzantine Fault-Tolerant (BFT) blockchain (e.g., Cosmos SDK / CometBFT or Narwhal-Bullshark DAG ledger) processing all council proposals, votes, price updates, and intra-year consumption transactions on-chain.
- **Architecture D — Hybrid Local-First + P2P Federated + Selective Epoch-BFT Architecture (Recommended):** Local-first SQLite/CRDT clients (`Role-LP`), peer-to-peer council/federation coordination (`Role-CC`), hierarchical Merkle-Sum Tree (MST) aggregation (`Role-PCW`), and a lightweight rotating BFT checkpoint layer (`Role-BFT`) invoked only for round finality, deterministic WASM IFB verification, and macro Society Account settlement.

### Recommended Polyglot Stack Decision
1. **Core Protocol, Cryptography, MST Aggregation, Local Solver, and Node Daemon (`dpep-core` & `dpep-node`):** **Rust** (compiled both natively for `Role-CC`, `Role-PCW`, `Role-BFT` on Linux/Raspberry Pi/macOS and to **WASM** for deterministic IFB execution). Note that **Clarabel.rs** (an interior-point conic/quadratic solver written in 100% safe Rust) and **HiGHS** allow every council and household client to solve constrained convex optimization problems locally in milliseconds!
2. **Mobile & Desktop Cross-Platform Client Library:** Expose `dpep-core` via **Mozilla UniFFI** (for native Kotlin/Swift bindings where hardware keystore access is needed) and **WASM** for a **TypeScript Local-First Progressive Web App (PWA)** that runs on any smartphone, tablet, or desktop browser without app-store gatekeeping.
3. **Epoch BFT Checkpoint Layer (`Role-BFT`):** Integrate with **CometBFT (Go)** via ABCI 2.0 (or a lightweight embedded Rust BFT engine) in production, while using a simple deterministic threshold-signed epoch coordinator in the initial Proof of Concept.
